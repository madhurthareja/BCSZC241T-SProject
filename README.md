# vidmark — Video Watermarking (DCT Spread-Spectrum)

A keyed, DCT-domain spread-spectrum watermark for video, with a Python
library, a FastAPI backend, a terminal-styled React frontend, and an
evaluation harness that benchmarks the scheme against Meta's VideoSeal and
`invisible-watermark`.

## Project Layout

- [src/vidmark/](src/vidmark/) — the core library (embedding, detection, video I/O).
- [app/](app/) — FastAPI backend exposing embed/detect/calibrate/bias-analysis endpoints.
- [frontend/](frontend/) — Vite + React UI ("vidmark-terminal") that talks to the backend.
- [scripts/](scripts/) — evaluation/calibration tooling: ROC curves, null-score calibration,
  cross-codec and frame-drop stress tests, and head-to-head comparisons against
  VideoSeal and `invisible-watermark`.
- [tests/](tests/) — pytest suite for the core library.
- [dataset/](dataset/), [figures/](figures/) — evaluation inputs/outputs generated by the
  scripts above (git-ignored; regenerate locally, see [Evaluation](#evaluation--benchmarking)).

## Algorithm Overview

1) **Key conditioning**
   - Input key string `K` is hashed with SHA-256.
   - The 256-bit digest is converted into a binary vector `b_i in {0,1}`.
   - Bits are mapped to a bipolar watermark sequence `w_i in {-1,+1}` via `w_i = 2*b_i - 1`.
   - The sequence can be repeated (`repeat` factor `r`) to increase length, `L = 256 * r`.
   - See [key_to_bipolar_sequence / expand_sequence](src/vidmark/core/algorithms.py).

2) **Frame-level deterministic randomness**
   - Coefficient positions are shuffled per frame with a keyed 64-bit Galois LFSR
     ([Lfsr](src/vidmark/core/algorithms.py)), not a general-purpose PRNG — every
     output bit is a fixed XOR of prior state, so the exact tap sequence is
     replayable from the seed alone at both embed and detect time.
   - For each frame index `t`, a mixed seed (`(t+1) * 0x9E3779B1 XOR key_seed`) drives
     the LFSR for that frame.

3) **Luminance-only processing**
   - Each frame is converted to YCrCb; only the Y channel is modified. Cr/Cb pass through
     untouched to reduce visible artifacts.

4) **Block DCT**
   - The Y plane is split into 8x8 blocks, centered by subtracting 128, and 2D-DCT'd.

5) **Coefficient selection**
   - A default candidate pool of 12 low/mid-frequency positions (`u+v <= 4`) is used,
     favoring coefficients that survive codec transform/quantization across H.264,
     HEVC, and AV1 (see `LOW_FREQ_POSITIONS` in
     [src/vidmark/core/algorithms.py](src/vidmark/core/algorithms.py)).
   - A keyed, per-frame LFSR shuffle selects a subset of size `max_positions` (default 6)
     from the pool for each block.

6) **Adaptive embedding strength (perceptual masking)**
   - Blocks with `sigma < sigma_floor` (default 5.0) are skipped entirely.
   - Otherwise the strength scale is bounded on both ends:

     ```
     scale   = clamp(sigma / sigma_ref, scale_min, scale_max)
     alpha_k = min(alpha * scale, alpha_cap)
     ```

     The lower bound (`scale_min`, default 0.5) keeps textured-but-modest blocks from
     getting an alpha so small the codec quantizes it away; the upper bound
     (`scale_max`, default 1.75) and `alpha_cap` (default 55.0) prevent visible spikes
     in high-variance blocks.

7) **Embedding rule**
   - For each selected coefficient `C(u,v)`: `C'(u,v) = C(u,v) + alpha_k * w_i`, consuming
     the watermark sequence sequentially across blocks and coefficients.

8) **Inverse DCT and reconstruction**
   - Each block is inverse-transformed, shifted back by +128, clipped to `[0,255]`, and
     the frame is reassembled from Y/Cr/Cb back to BGR.

9) **Output encoding**
   - Frames are piped as raw BGR directly into `ffmpeg` for a single libx264 encode at a
     given CRF ([VideoWriter](src/vidmark/io/video_writer.py)). Writing through OpenCV's
     writer and re-encoding would double-compress and quantize the watermark away, so
     `ffmpeg` on `PATH` is a hard requirement for embedding.

### Detection

Detection extracts the same coefficient positions and computes a normalized correlation:

```
T = sum_i (X_i - mean(X)) * w_i / (||X - mean(X)|| * ||w||)
```

Per-frame scores are aggregated into a [DetectionResult](src/vidmark/utils/result.py)
against a threshold. `Watermarker.detect()` also supports `sync_search`: a window of
constant frame-index offsets is tried and the offset with the strongest aggregate
correlation is kept, which recovers alignment when a re-encode shifts timestamp-derived
frame indices (e.g. a re-encoder dropping the first frame). Threshold calibration is
data-driven via [scripts/calibrate.py](scripts/calibrate.py) and the null-score datasets
under `dataset/`, rather than a single fixed constant — see
[Evaluation](#evaluation--benchmarking).

### Key Parameters (current defaults)

| Parameter       | Default | Notes                                      |
|-----------------|---------|---------------------------------------------|
| `block_size`    | 8       | DCT block size                              |
| `max_positions` | 6       | coefficients embedded per block              |
| `sigma_floor`   | 5.0     | blocks below this std-dev are skipped        |
| `sigma_ref`     | 20.0    | reference std-dev for strength scaling       |
| `scale_min`     | 0.5     | lower bound on the sigma-based scale factor  |
| `scale_max`     | 1.75    | upper bound on the sigma-based scale factor  |
| `alpha_cap`     | 55.0    | hard cap on `alpha_k`                        |
| `alpha` (strength) | low: 10.0 / medium: 20.0 / high: 30.0 | DCT-coefficient-domain units, not a pixel-range fraction |

**Parameter effects:** higher `alpha` increases robustness but raises visible distortion;
lower `max_positions` reduces artifacts but may reduce detectability; higher `sigma_floor`
avoids smooth areas (less flicker/banding); lower `alpha_cap` / `scale_max` prevent large
coefficient spikes in high-variance blocks.

## Installation

Requires Python >= 3.12 and `ffmpeg` on `PATH` (used for encoding watermarked output).

```bash
uv sync              # installs runtime + dev dependencies from uv.lock
# or: pip install -e .
```

## Usage

### As a library

```python
from vidmark import Watermarker

wm = Watermarker(key="secret", strength="high")
wm.embed("demo.mp4", "demo_watermarked.mp4")

result = wm.detect("demo_watermarked.mp4", threshold=0.2)
print(result.confidence, result.present)
```

See [main.py](main.py) for a minimal end-to-end example.

### Backend API

```bash
uv run uvicorn app.main:app --reload
```

Exposes (see [app/main.py](app/main.py) / [app/schemas.py](app/schemas.py)):

- `GET /health` — liveness check
- `POST /video/metadata` — fps, frame count, dimensions, duration
- `POST /watermark/embed` — embed a key into an uploaded video, returns the watermarked MP4
- `POST /watermark/detect` — detect a key, returns confidence/threshold/frame scores
- `POST /watermark/calibrate` — suggest a detection threshold from a clean/watermarked pair
- `POST /watermark/analyze-bias` — compare clean vs. watermarked confidence (false-positive gap)

### Frontend

A terminal-styled UI ("vidmark-terminal") for embed/detect/calibrate/bias workflows against
the backend above.

```bash
cd frontend
npm install
npm run dev          # expects the API at http://localhost:8000 by default
```

## Evaluation & Benchmarking

[scripts/](scripts/) contains the harness used to validate and calibrate the scheme:

- `calibrate.py`, `rebuild_null_calibration.py`, `expand_null_calibration*.py` — build
  wrong-key null-score distributions and derive detection thresholds.
- `make_roc_figure.py`, `make_heatmap_figure.py`, `make_frame_drop_figure.py`,
  `bootstrap_ci.py` — generate the figures in [figures/](figures/) (ROC curve, detection-rate
  heatmap, frame-drop recovery) with bootstrap confidence intervals.
- `cross_codec_stress_test.py`, `cross_codec_ab_test.py`, `frame_drop_test.py`,
  `noise_brightness_test.py` — robustness under re-encoding to different codecs, frame
  drops, and noise/brightness perturbations.
- `compare_videoseal.py`, `compare_videoseal_extended.py`, `measure_videoseal_memory.py`,
  `compare_invisible_watermark.py` — head-to-head comparisons against Meta's VideoSeal and
  `invisible-watermark`, run through the same harness (same source videos, same CRF sweep).
- `analyze_bias.py`, `sync_search_ablation.py`, `aggregate_paper_stats.py`,
  `measure_own_runtime.py`, `run_experiments.py`, `detect.py`, `prep_new_videos.py` —
  supporting analysis, ablations, and CLI utilities.

Evaluation inputs/outputs (source clips, null-score arrays, comparison CSVs) live under
`dataset/` and are git-ignored; regenerate them by running the scripts above rather than
expecting them to be checked in.

## Testing

```bash
pytest -vv --color=yes | tee pytest_output.txt
```

Notes ([tests/test_watermarking.py](tests/test_watermarking.py)):
- The end-to-end MP4 detection test with the correct key can fail on some systems because
  MP4 encoding can attenuate the DCT-domain watermark in small synthetic clips.
- Deterministic sequence generation, medium-strength transparency, incorrect-key rejection,
  and multi-frame aggregation are covered and pass locally.

## Limitations and Open Work

- Block alignment assumes no cropping, scaling, or rotation of frames.
- `sync_search` handles constant frame-index offsets, not variable frame drops mid-stream.
- Video encoding settings (codec, bitrate/CRF, resolution) affect artifact levels and
  detectability; results in `figures/` are specific to the codecs/CRFs they were run at.
